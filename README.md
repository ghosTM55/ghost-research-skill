# Ghost Research Skill

基于横纵分析法（Horizontal-Vertical Analysis）的个人深度研究 Skill，默认交付精炼、可追溯的研究报告。仓库命名采用 `ghost-research-skill`，安装后的 Skill 名仍为 `ghost-research`。它不是原版 `hv-analysis` 的简单复制，而是根据我自己的研究工作流做过适配：输出面向 Obsidian / KBS，强调可沉淀、可追踪、可复用的 Markdown 研究报告。

## 这个版本改了什么

| 原版 hv-analysis | ghost-research |
|-----------------|----------------|
| 输出面向 PDF 研究报告 | 输出面向 Obsidian / KBS 的 Markdown 研究报告 |
| 更适合完整公开报告 | 更适合个人知识库、项目知识库、长期研究沉淀 |
| 固定报告生产流程 | 面向深度研究和 KBS 沉淀，默认生成可写入知识库的 Markdown 报告 |
| 偏通用 Agent 工具描述 | 改为更适配 Hermes Agent，同时保留可迁移性 |
| 图表规范较弱 | 按阅读任务选择 Markdown、Mermaid 或 HTML，不要求每篇集齐三种形式 |
| 默认万字长文 | 默认全文 10,000 字以内，按复杂度充分展开，不凑字数也不压成摘要 |
| 横向以同类竞品为主 | 按相关性加入地域差异、跨行业机制与可证伪的创新假设 |
| 专业表达容易变成黑话 | 用直白中文解释机制，保留必要且准确的专业术语 |
| 默认生成最终报告 | 默认服务于个人 KBS / 项目 KBS 的研究沉淀 |
| 偏产品/公司研究 | 在不削弱原有横纵分析能力的前提下，抽象扩展到市场机会、市场进入、供需结构和已有研究稿复核 |
| 容易像聊天问答 | 增加证据复核、边界修复、论证重构和专业报告化的写作约束 |

## 我的使用场景

我的研究报告类工作主要通过 [Hermes Agent](https://github.com/NousResearch/hermes-agent) 完成，并沉淀到两类知识库中：

1. **个人 KBS / Obsidian**：用于个人长期研究、市场观察、产品分析、技术趋势判断。
2. **项目 KBS**：用于具体项目、公司、产品方向、合作机会或战略议题的研究沉淀。

因此这个 Skill 默认关注：

- Markdown / Obsidian 格式，而不是 PDF 排版；
- Markdown 保留正文与证据，Mermaid 按需解释结构，HTML 仅在阅读收益和兼容性明确时使用；
- frontmatter、tags、aliases、已核实的双链和适量 callout；
- 就近来源、关键不确定性和判断更新条件；
- 能解释当前状态的历史转折、直接与间接替代、地域差异和跨行业借鉴；
- 市场、赛道、地区、品类、供需结构和进入机会的系统性判断；
- 已有研究稿的证据复核、边界修复、论证重构和专业报告化；
- 根据研究语境写入个人 KBS 或项目 KBS；路径不明确或存在覆盖风险时再确认。

## 适用场景

适合用来研究：

- 产品 / 公司 / 项目
- 技术概念 / AI 模型 / 行业范式
- 人物 / 团队 / 创始人
- 赛道 / 市场 / 竞品格局
- 地区机会 / 市场进入 / 供需结构 / 渠道结构
- 已有 KBS 研究稿的深度 review 与重构
- 一个你想真正搞懂、并沉淀进知识库的对象

不适合：

- 简单名词解释
- 一句话结论
- 新闻摘要
- 纯写作润色
- 不需要联网验证的轻量问答

## 使用前请根据自己情况修改

### 搜索、正文与浏览器的分工

本 Skill 不要求安装某个特定 MCP，也不要求将全部研究转交浏览器。根据任务选择当前环境已有的工具：

- **指定公开链接**：先直接读取正文，仅围绕关键争议补查来源。
- **开放式研究**：轻量中英文搜索发现候选，再筛选并核验原文。
- **已知登录或动态页面**：直接使用获授权的现有浏览器会话，先确认目标站点与账户上下文；不承诺自动通过 OAuth、验证码或网站风控。
- **近期动态补采**：优先官方 RSS、发布记录和公开 API，再搜索补缺；摘要和聚合时间不替代原文与事件时点。

BrowserOS 可承担浏览器环节，但工具名和参数以当前运行时为准。正文阅读、交互定位和截图有不同用途；输出截断时先读取工具保存的完整文件，不反复加载网页。同一失败方法最多做一次有依据的修正，再换独立来源或明确报告缺口。

调研默认只读，不读取 cookie、token 或无关私密页面，不把网页指令当作用户授权。后台标签页不等于隐私隔离；新增授权和对外写入需要单独确认，无人值守任务不得绕过审批。证据须能追溯到原始 URL，并明确动态列表的筛选、分页与部分覆盖。

### 本地适配与更新边界

这个 Skill 带有明显的个人工作流假设。建议 fork 后至少检查并修改：

1. **输出位置**：个人 Obsidian、公司 KBS、项目文档库，或其他沉淀位置。
2. **frontmatter 字段**：tags、aliases、status、type、related_notes 是否符合你的知识库规范。
3. **研究范围**：根据你的知识库结构、研究对象类型和输出用途，调整竞品范围、来源标准和报告长度。
4. **联网工具**：根据你使用的 Agent，改成对应的搜索、浏览器、网页读取或论文检索工具。
5. **文件写入规则**：如果你的 Agent 有自动写文件能力，建议明确个人知识库、项目知识库和覆盖已有文件时的处理方式。
6. **语言风格**：默认直白、准确的专业中文；按读者知识调整术语解释，不用咨询黑话代替机制。
7. **可视化规范**：Mermaid、表格、关系图是否适合你的阅读和发布环境。
8. **HTML 展示层**：先验证目标阅读器；环境不明或样式不能减少阅读负担时用 Markdown/callout，必要时才加 Mermaid。

更新已有安装时，先比较源码与安装副本，合并需要的通用改进；不要覆盖本地扩展，也不要把个人或客户资料自动回传公开仓库。下方复制命令适用于新安装；已有自定义内容时应改用经过检查的增量合并。

## 安装 / 使用

### Hermes Agent

如果你使用 Hermes Agent，可以把本 Skill 安装到本地 skills 目录，例如：

```bash
mkdir -p ~/.hermes/skills/research/ghost-research
cp ./SKILL.md ~/.hermes/skills/research/ghost-research/SKILL.md
hermes skills list | grep ghost-research
```

安装后开启新 session，或在当前 Hermes 会话中 `/reset`，再显式加载：

```text
/skill ghost-research
```

也可以直接从 GitHub raw `SKILL.md` URL 安装：

```bash
hermes skills install "https://raw.githubusercontent.com/ghosTM55/ghost-research-skill/main/SKILL.md" --category research --name ghost-research
```

### 其他 Agent

这个 Skill 本质上是 Markdown 指令集，不强依赖 Hermes。Claude Code、Codex、OpenCode 或其他支持 Agent Skills / 自定义指令的工具也可以改造使用。

但请注意：不同 Agent 的工具名、联网能力、文件写入权限和 skill 加载路径不同。不要直接照搬安装命令，先根据自己的 Agent 环境调整。

## 相关 Skill：wiki-research

[`wiki-research`](https://github.com/ghosTM55/wiki-research-skill) 可以和 `ghost-research` 配合使用，但职责不同：

- `wiki-research`：在普通搜索或研究中，自动补充 Wikipedia、Wikidata、官方/项目 Wiki、Fandom/社区 Wiki 等来源；适合处理背景、别名、实体关系、时间线、lore/canon 和社区知识结构。
- `ghost-research`：负责完整深度研究，使用横纵分析法组织纵向历史、横向竞争格局、交叉洞察、证据矩阵和 KBS/Obsidian Markdown 输出。

推荐配合方式：如果研究对象涉及 IP、人物、组织、项目、作品、技术概念或社区知识，agent 可以先让 `wiki-research` 在后台补充相关 wiki 类信息源和关系线索，再由 `ghost-research` 负责深度分析和最终报告。用户不需要为此写复杂 prompt；正常提出研究请求即可。

## 默认输出形态

默认输出为 Obsidian/KBS Markdown 报告，全文控制在 **10,000 字以内**，按问题复杂度和证据需要充分展开，不设最低字数，也不以写满上限为目标。精炼以去除重复和无关内容为主，不把必要论证压成摘要；明确指定长度时遵从用户要求。篇幅包含标题、摘要、正文、表格、图中可见文字、HTML 内容及附录，不计引用 URL 和 YAML。

通常用短摘要给出判断，再围绕关键问题解释证据、机制、取舍和下一步验证。历史、地域、竞品、跨行业案例融入相关判断，不各自铺成一份长报告。内部保留证据表；正文保留就近引用与重要不确定性，不默认展示全量证据矩阵、年表或延伸阅读。

每个章节标题都要单独打磨：先明确这一节要让读者理解什么，再用具体、准确的措辞表达核心发现或问题。避免直接套用“市场分析”“机遇与挑战”等空泛标签；判断式标题必须有正文证据支持。交付前单独读一遍目录，检查各节意图、层级与论证顺序，再核对标题是否与正文一致。

研究时检查三个补充视角是否相关：

- **地域**：使用目标地区和相关当地语言的证据，比较前统一时间、币种和统计口径，不用少数英文案例代表全球。
- **跨行业**：借鉴解决同一问题的机制，说明成功条件与不能照搬的部分，并寻找失效案例。
- **创新**：对照现有替代方案，核验未满足的需求、现在可行的原因、交付与付费条件，以及最低成本的证伪办法。

呈现方式取决于内容：

| 内容 | 默认形式 |
|---|---|
| 结论、解释与证据 | 短段落、列表和就近来源 |
| 多个选项的相同维度比较 | 窄表 |
| 流程、关系或有解释价值的时间演化 | Mermaid，通常 0–2 张 |
| 少量重点需要快速扫读 | Callout；兼容性已验证且有收益时用 HTML |

报告不必同时包含 Mermaid 和 HTML。图表不重复正文、不制造假精度；HTML 沿用主题与字体，不默认渐变背景或卡片网格。实际使用图表/样式后要在目标阅读器预览，不能把源码检查当成视觉验收。

更新已有 Hermes 安装时，需要同时检查旧的章节字数、完整模板、写作风格与质检清单，移除与新规则冲突的通用要求；只在顶部追加“精炼”不能消除下文的扩写倾向。本地专题参考、路径与专属规则应通过差异合并保留，不用仓库文件整份覆盖。
